# 「今天去哪」产品方案（第五个底部标签）

- 项目：出来去哪玩（WQWN）· 纯前端静态原型（无构建、无后端，localStorage key `wqwn.v3`）
- 版本：v1.0（2026-11-13）
- 作者：product-designer
- 状态：开发依据 / 待 Lead 评审
- 范围：只定义第五标签「今天去哪」的产品方案与验收标准，不涉及业务代码修改

---

## 0. 决策摘要（TL;DR）

- **一句话定位**：「今天去哪」是底栏里的一只城市签筒——不搜索、不比较，从站内真实地点里随机抽一个，给用户一个今天就能出发的答案。
- **底部 5 个 tab 的顺序（已定）**：`首页 / 去哪 / 发布 / 搭子 / 我的`。「发布」保持第 3 位、保留橙色圆形凸起；新增的「去哪」在第 2 位，承接首页的“逛”并转入“定”。
- **命名**：底部标签用 2 个字「去哪」，和现有「首页 / 发布 / 搭子 / 我的」保持等长节奏；页面内标题用完整的「今天去哪」。
- **核心体验**：进入即自动抽一签（无需先点按钮）→ 单张结果卡 → 「再摇一次」换一个（不连续重复）→ 「就去这里」进现有详情页。
- **技术边界**：只读复用 `W.Store.listSpots()` 与现有详情页，**不新增后端、不新增数据字段、不新增网络请求、不写 localStorage**。
- **体验底线**：从点开 tab 到进入详情，最少 2 次点击（点「去哪」→ 点「就去这里」）；单次抽签 1.2 秒内出结果；连续再摇不出现相邻重复。

## 1. 一句话产品定位与用户旅程

### 1.1 产品定位

> **「今天去哪」是给“不知道去哪”的人的一枚城市签：不做攻略，不列清单，摇到一个就出发。**

它不解决“城市里有什么”（首页负责），也不解决“这个地方怎么样、怎么去”（详情页负责）。它只解决一件事：**在若干个都还不错的地点里，替用户做一次决定。**

### 1.2 用户与场景

| 维度 | 说明 |
|---|---|
| 核心用户 | 周末/下班后想出门、但没有明确目的地的年轻人；朋友临时约出门、谁都不想拍板的小团体 |
| 典型场景 | 周六下午 14:00，人在杭州，想出门但刷了十分钟首页还没决定；不想做攻略，不想收藏一堆“下次去” |
| 用户情绪 | 选择过载、轻微拖延、想要一个“就它了”的理由 |
| 成功感受 | “行，就这儿，走。”——而不是“我又收藏了 5 个地方” |
| 非目标场景 | 已经明确要去某地的人（用首页搜索/详情）；需要多人投票、行程规划的人（本期不做） |

### 1.3 用户旅程（从打开 App 到决定去哪）

**主线（最短路径）**

| 步骤 | 用户动作 | 系统反馈 | 用户心理 |
|---|---|---|---|
| 1 | 打开 App，落在首页 | 城市封面、地图、地点卡 | “都还行，但选不出来” |
| 2 | 点底部「去哪」 | 进入「今天去哪」，自动开始翻签 | “不用动脑了” |
| 3（可选） | 点「今天想」里的某个心情 | 签筒缩小到对应分类，重新翻签 | “范围有点像我了” |
| 4 | 看结果卡 | 图片、类别、标题、城市/价格、一句真实评价 | “有画面了” |
| 5a | 不满意 → 点「再摇一次」 | 避开刚才那张，重新翻签 | “再试试” |
| 5b | 满意 → 点「就去这里」 | 进入该地点详情页 | “就它了” |
| 6 | 详情页看地址/评论，点「导航前往」 | 打开高德 | “出门” |

**分支路径**

- 当前心情下没有地点 → 空态：换一个心情 / 去首页看看。
- 全站还没有地点 → 空态：去发布第一个地点。
- 数据读取异常 → 错误态：重新抽一次 / 去首页。
- 抽到一半切走再回来 → 保留本次会话已抽到的结果，不重新摇。

**衡量（原型阶段只看行为，不做埋点系统）**

- 抽签完成率：进入页面后能看到结果卡的比例。
- 换签次数：平均 ≤ 2.5 次；超过 5 次说明池子质量或筛选有问题。
- 结果 → 详情点击率：这是这个页面是否真的帮用户做决定的直接证据。
- 5 个 tab 的点击命中率：验证底栏扩容后没有误触。

### 1.4 设计原则

1. **一次只给一个答案。** 结果区永远只有一张卡，不做“猜你喜欢”列表。
2. **不做第二个首页。** 没有地图、没有搜索框、没有距离筛选、没有无限流。
3. **随机，但不随便。** 只从站内真实地点里抽，展示真实评价，不按热度加权、不设推广位。
4. **随时可以退出。** 任何状态都有「去首页」或「就去这里」，不把用户困在抽签里。
5. **轻。** 不登录、不授权定位、不发请求、不产生任何写操作。

## 2. 功能边界

### 2.1 本期做什么（P0）

| 能力 | 说明 |
|---|---|
| 第五个底部标签 | `data-tab="whereto"`，文案「去哪」，位置第 2；`#/whereto` 路由，直接访问可打开 |
| 自动抽签 | 首次进入即从当前签筒抽 1 个地点，600–900ms 翻签动效后出结果；无需先点按钮 |
| 心情/分类筛选 | 单行 chips，7 项：都可以 / 吃点好的 / 玩点新鲜的 / 看看风景 / 拍点照片 / 夜游一下 / 随便逛逛；分别映射 `all/food/fun/nature/photo/night/other`，复用 `W.UI.categories` 的 key，不新增分类 |
| 再摇一次 | 从当前筛选池重新抽；使用洗牌袋算法，连续抽不重复；池中仅 1 个时保持原结果并 toast 提示 |
| 结果卡 | 封面图、抽签编号、分类（英文 + 中文）、标题、城市 + 价格、最高赞的一条真实评论、「就去这里」「再摇一次」 |
| 跳详情 | 「就去这里」调用 `W.Router.go('#/spot/' + spot.id)`，进入现有详情页 |
| 空态 | 分类池为空 / 全站无地点两种文案与动作 |
| 异常兜底 | `W.Store.listSpots()` 抛异常、地点字段缺失/脏数据时安全降级，不白屏 |
| 5 列 tabbar | 现有 `#tabbar` 从 4 列改 5 列，360px 宽度下不换行不溢出，发布按钮仍在正中 |
| 基础可访问性 | tab `aria-current`、chips `aria-pressed`、结果区 `aria-live="polite"`、图片 alt、抽签动效尊重 `prefers-reduced-motion` |

### 2.2 本期做什么（P1，可不阻塞上线）

- 本次会话内保留上一次结果与心情筛选（切 tab 回来不重抽；刷新重置）。
- 结果卡显示“签筒 · 从 N 个地点里抽到这一签”的池子计数，让随机可感知。
- 抽签编号 `NO. 01` 起递增（本次会话内计数，刷新归零），强化“今日一签”的仪式感。
- 翻签过程中轮播地点标题，让等待可感知；不显示空白骨架。

### 2.3 本期不做什么（明确边界）

| 不做 | 原因 |
|---|---|
| 不做真实“每日固定一签” | 无后端、无账号体系；本地方案刷新即变，做成“每日”会名不副实 |
| 不做 AI 推荐 / 个性化画像 | 无模型、无用户行为数据；伪 AI 文案只会增加不信任 |
| 不做地图、距离筛选、搜索 | 首页已经承担“在哪、多远”；重复会让第五标签变成第二个首页 |
| 不做收藏/点赞/评论的写操作 | 详情页已有完整能力；抽签页只负责“决定”，不叠加操作 |
| 不做抽签历史、签文收藏、分享海报 | 需要新数据模型与存储，超出本期原型边界 |
| 不做“不喜欢/屏蔽这个地点” | 负反馈需要长期记忆与推荐逻辑，本期用「再摇一次」已足够 |
| 不做付费推广/热度加权 | 随机必须公平；否则“盲盒”失去可信度 |
| 不做多人投票/一起决定 | 属于搭子协作能力，后续可基于搭子页扩展 |
| 不改 `W.Store`、`js/seed.js`、数据模型 | 仅读现有数据，保证 25 项既有功能零回归 |
| 不新增第三方库、字体或网络请求 | 保持零构建、离线可用的原型约束 |

### 2.4 数据与依赖边界

**只读数据源（唯一）**

```js
// 当前筛选池：category 为 'all' 或现有枚举
var pool = W.Store.listSpots({ category: filterKey });

// 结果跳转：复用现有详情路由
W.Router.go('#/spot/' + spot.id);
```

- 使用字段：`id`、`title`、`category`、`city`、`price`、`cover`、`images`、`comments`（取最高赞一条）。
- `W.Store.listSpots()` 返回深拷贝，视图**不得修改**返回值；抽签页对 Store 零写入。
- 新发布的地点会自动进入签筒（因为每次渲染都重新调用 `listSpots`，不缓存种子快照）。
- 不调用 `navigator.geolocation`：本页不需要定位，也不应触发权限弹窗。
- 复用组件：`W.UI.el`、`W.UI.icon`、`W.UI.money`、`W.UI.categoryName`、`W.UI.toast`、`W.UI.empty`（空态可用自定义结构，但视觉沿用 `.empty` 体系）。
- 复用样式 token：`--paper / --ink / --muted / --line / --accent / --serif / --mono / --pad`，不新造主题色。

## 3. 页面信息架构与交互状态

### 3.1 页面信息架构（从上到下）

| 顺序 | 区块 | 内容 | 目的 |
|---|---|---|---|
| 1 | 全局刊头 | 现有 `#app-header`：品牌 + 城市 + 日期 | 保持全站编辑感，不重复实现 |
| 2 | 页面刊头 | 眉题 `TODAY'S DRAW · 今日一签`；大标题「今天去哪」；副文案「不做攻略，把今天交给城市。」 | 3 秒内说清这页是干什么的 |
| 3 | 心情区 | 标签「今天想 / MOOD」+ 7 个单行可横滑 chips | 给用户一个“可控的随机” |
| 4 | 抽签舞台 | 翻签动画 / 结果卡；高度预留，避免结果出现时页面跳动 | 页面唯一主角 |
| 5 | 签筒脚注 | `签筒 · 从 N 个地点里抽到这一签` + 抽签编号 | 让随机透明、可感知 |
| 6 | 底部留白 | 适配 `--tabbar-h` + safe-area | 不被 tabbar 遮挡 |

**结果卡的信息层级（从上到下）**

1. 封面图（`cover` → `images[0]` → 纸张色分类占位图）。
2. 编号：`NO. 03`（本次会话抽签序号，两位补零）。
3. 分类：英文眉题（FOOD / PLAY / NATURE / PHOTO / NIGHT / CITY）+ 中文分类名。
4. 标题：地点名，最多两行。
5. 元信息：`{城市} · {价格}`（0 元显示“免费”）。
6. 真实评价：该地点 `comments` 中评分最高、同分取最新的一条，截取前 60 字，署名作者；无有效评论则整块不渲染。
7. 操作区：主按钮「就去这里 →」；次按钮「再摇一次 ↻」。

### 3.2 交互状态机

| 状态 | 触发 | 界面表现 | 可用操作 |
|---|---|---|---|
| **S0 首次进入 / 翻签中** | 首次打开 `#/whereto`（无会话结果） | 页面骨架完整；抽签区显示「正在翻签…」+ 地点标题快速轮播；结果卡高度已预留；按钮暂时禁用 | 无（等待 600–900ms） |
| **S1 结果态** | 翻签结束 | 显示且仅显示一张结果卡；chips 可点；结果区 `aria-live` 播报 | 再摇一次 / 就去这里 / 切换心情 / 切 tab |
| **S2 再摇一次** | 点「再摇一次」 | 原卡短暂切换为翻签态（400–600ms），随后替换为新卡；页面不滚动、不闪白 | 等待，期间按钮禁用 |
| **S3 心情筛选重抽** | 点任一心情 chip | chip 选中态切换；池计数立即更新；自动重抽一张（无需二次点击） | 等待后看结果 / 继续换心情 |
| **S4 空态** | 当前筛选池为 0 | 不显示结果卡；显示「这一签，签筒是空的。」+ 原因说明 + 恢复动作 | 换个心情 / 去首页 / 去发布（全站为空时） |
| **S5 异常态** | `listSpots` 抛错或返回非数组 | 显示「今天抽不了签。」+ 简短原因 + 重试 | 重新抽一次 / 去首页 |
| **S6 会话恢复** | 切走 tab 后再回来，或从详情浏览器返回 | 直接显示上次结果与心情筛选，不播放翻签动画 | 再摇一次 / 就去这里 |

**状态流转**

```
进入 #/whereto
   ├─ 有会话结果 ──────────────→ S6 直接恢复
   └─ 无会话结果 ──→ S0 翻签 ──→ S1 结果
                                   ├─ 再摇一次 → S2 → S1
                                   ├─ 换心情 → S3 → S1
                                   ├─ 池为空 → S4
                                   └─ 读取失败 → S5
```

### 3.3 随机规则（唯一实现口径）

- **公平**：`Math.random` 均匀抽取，不按 `views`/`likes`/`favorites` 加权，不插广告位。
- **不连续重复**：每个筛选池维护一个“洗牌袋”（shuffle bag）。把池中地点洗牌后依次取出；取完再洗一轮。新一轮的第一张若与上一张相同，与下一张交换，确保**相邻两次必不相同**（池 ≥ 2 时）。
- **筛选切换**：按分类 key 维护各自的袋子；切换心情时重建该分类的袋子，避免跨分类串结果。
- **池只有 1 个**：保持该结果，toast「签筒里只剩这一张了。」；不假装换了一张。
- **不持久化**：抽签结果、编号、袋子都只存内存；刷新页面重新抽。不做 localStorage 写入。
- **数据新鲜度**：每次抽签前重新读取 `listSpots({ category })`，新发布地点无需刷新即可入池。

### 3.4 空态与异常数据矩阵

| 场景 | 判定条件 | 界面 | 动作 |
|---|---|---|---|
| 当前分类为空（全站有地点） | `pool.length === 0` 且 `listSpots().length > 0` | 标题「这一签，签筒是空的。」；说明「“{心情名}”下还没有地点。换个心情，或者去首页添一个。」 | 「换个心情」重置为「都可以」并重抽；「去首页」→ `#/home` |
| 全站无地点 | `W.Store.listSpots().length === 0` | 标题「签筒里还没有地点。」；说明「先去发布一个，再来抽今天去哪。」 | 「去发布」→ `#/publish` |
| 数据读取异常 | `listSpots()` 抛异常或返回非数组 | 标题「今天抽不了签。」；说明「地点数据没读出来，再试一次。」；页面不白屏 | 「重新抽一次」触发重渲染；「去首页」→ `#/home` |
| 标题缺失/为空 | `!spot.title` | 显示「未命名地点」 | 正常可抽、可跳详情 |
| 封面缺失/加载失败 | 无 `cover`、无 `images` 或 `img.onerror` | 纸张色占位块 + 分类英文标记（沿用首页 fallback 视觉） | 不出现破图图标 |
| 价格非法 | `Number(price)` 为 NaN 或 < 0 | 显示「价格待定」 | 不显示 `NaN` / `undefined` |
| 城市缺失 | `!spot.city` | 显示「城市未填」 | — |
| 分类未知 | category 不在枚举内 | 按「其他 / CITY」处理 | — |
| 评论为空/脏数据 | `comments` 非数组、为空、全部无有效内容 | 不渲染评价块 | 卡片其余部分正常 |
| 评论内容为空白 | `String(content).trim() === ''` | 跳过该条，继续找下一条有效评论 | 不出现空引号 |

### 3.5 响应式与可访问性

- **360px / 430px 移动端**：页面无横向滚动；tabbar 5 列等宽（360px 下每列 72px），图标 20px、文字 8px 单行；发布圆钮 46px 在 72px 列内不溢出。
- **桌面端（≥720px）**：沿用现有 430px 手机画布规则，不单独设计桌面布局。
- **触控目标**：所有按钮和 chips 的点击高度 ≥ 44px；「再摇一次」与「就去这里」并排时也不小于 44px。
- **无障碍**：
  - tab 使用 `aria-current="page"` 标记当前项；图标 `aria-hidden="true"`。
  - 心情 chips 用 `<button>` + `aria-pressed="true|false"`，选中态不能只靠颜色表达（加下划线或实底）。
  - 结果区 `aria-live="polite" aria-atomic="true"`，翻签结束时只播报一次“抽到 {title}”。
  - 封面图 `alt="{title} 的封面"`；装饰性编号 `aria-hidden="true"`。
  - `prefers-reduced-motion: reduce` 时跳过翻签动画，直接出结果。
  - 不使用自动聚焦抢走用户焦点；「再摇一次」保留焦点。

## 4. 验收案例（12 条）

> 基线：首次打开、种子数据（10 个地点：food 2 / fun 1 / nature 3 / photo 2 / night 1 / other 1；4 个搭子）。验收以**可见文案与 URL**为准，不依赖内部 class 名。

### AC-01 五个底部标签的顺序与状态

- **Given** 应用已启动，任意页面
- **When** 查看底部导航
- **Then** 从左到右依次为「首页 / 去哪 / 发布 / 搭子 / 我的」，共 5 项；「发布」在第 3 位并保持橙色圆形凸起；点击五项分别到达 `#/home`、`#/whereto`、`#/publish`、`#/buddies`、`#/profile`；当前项有 `aria-current="page"` 且视觉高亮唯一。

### AC-02 首次进入自动抽签并出现结果卡

- **Given** 种子数据、未访问过 `#/whereto`
- **When** 点击「去哪」或直接打开 `#/whereto`
- **Then** 页面显示「今天去哪」与 `TODAY'S DRAW · 今日一签`；1.2 秒内出现且仅出现 1 张结果卡；卡内地点标题能在 `W.Store.listSpots()` 的 10 条种子中找到；「去哪」tab 高亮；页面**不弹出定位授权**、不发网络请求。

### AC-03 心情筛选只出对应分类

- **Given** 在 `#/whereto`，当前心情为「都可以」
- **When** 点击「吃点好的」
- **Then** 该 chip 变为选中态且其余取消；签筒计数等于 `W.Store.listSpots({category:'food'}).length`（种子为 2）；抽出的结果 `category` 必为 `food`；再点「再摇一次」仍只在 food 池内变化。

### AC-04 再摇一次会换且不连续重复

- **Given** 当前筛选池 ≥ 3 个地点
- **When** 连续点击「再摇一次」3 次，每次等待翻签结束
- **Then** 每次结果都发生变化，且相邻两次的地点 ID 不同；翻签期间按钮短暂禁用、不产生重复点击；浏览器控制台无报错。

### AC-05 池中只剩一个地点

- **Given** 通过数据构造或筛选使当前池只有 1 个地点
- **When** 点击「再摇一次」
- **Then** 结果仍为该地点，页面不清空、不报错，并出现 toast「签筒里只剩这一张了。」。

### AC-06 就去这里跳详情且标题一致

- **Given** 结果卡显示地点 A
- **When** 点击「就去这里」
- **Then** URL 变为 `#/spot/{A.id}`；详情页 `h1` 标题与卡片标题一致；详情页正常展示封面、地址、评论；底部「首页」按现有路由契约高亮（详情页归属 home）。

### AC-07 切走再回来保留本次结果

- **Given** 已在 `#/whereto` 抽到地点 A，并已选择某个心情
- **When** 切换到「首页」后再切回「去哪」（或从详情页用浏览器后退返回）
- **Then** 仍显示地点 A，心情筛选保持；不重新播放翻签动画；仅整页刷新后才重新抽签。

### AC-08 空态与恢复

- **Given** 将 localStorage 的 `wqwn.v3` 设置为 `spots: []`（保留 users 结构）并刷新 `#/whereto`
- **When** 页面渲染
- **Then** 显示「签筒里还没有地点。」与「去发布」入口；点击去发布到达 `#/publish`；页面无 JS 错误、不白屏。
- **补充（分类空态）**：全站有地点但某分类为 0 时，显示「这一签，签筒是空的。」+「换个心情」；点击后回到「都可以」并重新出签。

### AC-09 脏数据兜底

- **Given** localStorage 中构造一条仅含 `id` 的地点（无 title / cover / price / city / comments）
- **When** 打开 `#/whereto` 并抽到它
- **Then** 卡片显示「未命名地点」「价格待定」「城市未填」等安全占位；无 `undefined`、`NaN`、破图；无 JS 错误，仍可点「就去这里」。

### AC-10 数据读取异常错误态

- **Given** 在控制台临时把 `W.Store.listSpots` 替换为 `function(){ throw new Error('boom') }`
- **When** 打开 `#/whereto`
- **Then** 显示「今天抽不了签。」与「重新抽一次」；页面不白屏、不抛未捕获异常；恢复原函数后点击重试可正常出签。

### AC-11 移动端宽度与 5 列布局

- **Given** 视口 360×800 与 430×932 两种尺寸
- **When** 打开 `#/whereto` 并抽到结果
- **Then** `document.documentElement.scrollWidth <= window.innerWidth`（无横向滚动）；tabbar 正好 5 等分，五项文字不换行、不截断；结果卡图片不变形；「就去这里」「再摇一次」高度 ≥ 44px 且可点击。

### AC-12 新发布地点自动进入签筒

- **Given** 已通过发布页或 `W.Store.addSpot()` 新增一个 `category:'food'` 的地点「测试地点」
- **When** 打开 `#/whereto`，查看签筒计数，再切到「吃点好的」
- **Then** 总签筒数由 10 变为 11，food 池由 2 变为 3；无需刷新页面即可读到新地点；多次抽签能抽到它（洗牌袋轮完必现）。

## 5. 与已有页面的关系与差异化价值

### 5.1 五个 tab 的分工

| 页面 / 标签 | 回答的问题 | 主要动作 | 与「今天去哪」的关系 |
|---|---|---|---|
| **首页** | “这座城市有什么、在哪、口碑如何？” | 地图浏览、搜索、分类/距离筛选、看地点卡 | 提供候选池；「今天去哪」只从池子里抽一个，不重复地图和复合筛选 |
| **今天去哪（新增）** | “现在到底去哪？” | 选心情、抽一签、再摇一次、去详情 | 把“浏览”收口成“决定” |
| **详情** | “这个地方怎么样、怎么去？” | 看图、看评价、收藏/点赞、导航 | 承接结果，完成从“决定”到“出发”的最后一跳 |
| **发布** | “我想推荐一个地方” | 填表、选图、提交 | 新地点自动进入签筒，扩充随机池 |
| **搭子** | “和谁一起去？” | 发起搭子、申请、审批 | 本期不打通；未来可在结果页加“发起搭子并关联此地点” |
| **我的** | “我发布/发起/加入/点赞过什么？” | 管理个人内容 | 本期不记录抽签历史；收藏仍归详情页与「我的」 |

### 5.2 不重复的差异化价值

1. **首页是“多”，这里是“一”。** 首页越丰富，选择成本越高；「今天去哪」故意只给一个答案，这是它存在的理由。
2. **不做第二个地图。** 地图回答“在哪”，不回答“选哪个”；抽签页不加载 Leaflet、不请求瓦片、不申请定位，打开即用。
3. **不做第二个详情。** 详情页负责“深看”，抽签页只负责“决定”；不在结果卡上堆收藏、评论、导航。
4. **不做第二个收藏夹。** 收藏是回忆和管理，不是决策；收藏入口继续留在详情页，「我的」后续补“我收藏的”分区即可，不需要单开 tab。
5. **首页看“大家说好”，这里看“今天属于我”。** 同一份真实评价数据，首页用于横向比较，结果卡只取最高赞的一条，作为“就它了”的最后推力。
6. **新内容自动入池。** 发布一个新地点后无需运营配置，下一次抽签就可能抽到；这让“发布 → 抽签 → 详情”形成闭环。

### 5.3 已知体验缺口（本期接受）

- 详情页左上角返回按钮现有实现固定回 `#/home`，从「今天去哪」进入详情后点返回会回到首页，而不是回到抽签结果。本期不改 `js/views/detail.js`；浏览器后退可回到 `#/whereto` 且保留结果。建议下一迭代把详情返回改为 `history.back()` 或按来源路由返回。

## 6. 为什么「今天去哪」适合作为第五个标签

### 6.1 判断标准

一个底部 tab 要同时满足四点才值得占位：

1. **高频**：用户会反复回来，而不是一次性功能。
2. **独立目的地**：它是一个“去哪儿”的页面，不是一个按钮或弹层。
3. **数据就绪**：现有数据能撑起来，不需要先建后端、先养内容。
4. **不与现有 tab 抢活**：回答一个现有页面没有回答的问题。

「今天去哪」四点全中：每次出门都会遇到“不知道去哪”；它是完整页面；10 个种子地点 + 用户发布地点即可运转；它补的是“决定”这一环，而不是再造“浏览”。

### 6.2 考虑过的替代方案

| 替代方案 | 它回答的问题 | 为什么不选它做第五标签 |
|---|---|---|
| **收藏** | “我存过什么？” | 这是管理型、低频繁需求；入口天然属于详情页和「我的」。单独开 tab 会出现一个空收藏夹，且不解决“不知道去哪”。README 也记录「我收藏的」分区尚未接入，应补在个人中心，而不是占用底栏。 |
| **地图** | “这些地方在哪？” | 首页已经是地图聚合；再开一个地图 tab 会出现两个地图入口，用户不知道点哪个，且地图本身不替用户做决定。 |
| **消息 / 通知** | “谁找我了？” | 无后端、无社交关系链，本期没有真实消息可展示，只会是空壳。 |
| **城市护照 / 打卡** | “我去过哪些地方？” | 需要签到数据、徽章体系、历史记录与奖励设计，属于 R10 后续功能；先做会变成“点了没反应”的假功能。 |
| **路线串点（半日游/一日游）** | “一天怎么安排？” | 依赖“先选地点、再算路线”，复杂度高；应该建立在“今天去哪”已经能选出地点之后。 |
| **避雷 / 实况评论** | “这个地方值不值得？” | 属于详情页的内容增强（R13），不是独立入口；单开 tab 会得到一条没有供给的 feed。 |
| **AI 推荐 / 猜你喜欢** | “系统觉得我想去哪？” | 无后端、无模型、无行为数据；伪 AI 文案不可信，也违背“真实地点、真实评价”的产品气质。 |

### 6.3 底栏经济学

5 个 tab 是移动端底栏的舒适上限。现有 4 个已经覆盖「逛（首页）/ 发（发布）/ 约（搭子）/ 我（我的）」，缺的正是「定」。「今天去哪」补上后，底栏形成一条完整动词链：

> **逛 → 定 → 发 → 约 → 我**

同时，5 列布局让「发布」自然落在正中，保留现有橙色圆钮的视觉锚点；新增 tab 放在第 2 位，既不打扰首页的首位地位，也给新功能足够的曝光。

## 8. 开发需注意（交接给实现与 QA）

1. **视图重渲染与定时器清理**：`W.Router.go()` 在相同 hash 下也会重新调用 `render()`。`js/views/whereto.js` 必须把结果、筛选、洗牌袋、抽签序号放在模块闭包中；每次 `render` 开始先清理上一次的 `setTimeout` / `setInterval`，否则翻签定时器可能写入已卸载的 DOM。已有有效结果时直接恢复，不要重复自动抽签。
2. **tabbar 从 4 列改 5 列**：`css/style.css` 中 `#tabbar { grid-template-columns: repeat(4, 1fr); }` 必须改为 `repeat(5, 1fr)`；「发布」继续保持第 3 项与 `translateY` 圆钮样式；在 360px 宽度下检查 `去哪` 文案不换行、发布圆钮不溢出。`index.html` 的 tab 顺序与 `js/app.js` 的 `ROUTES`、`tab` 值三者必须一致，否则 `aria-current` 不亮。
3. **详情返回的已知缺口**：`js/views/detail.js` 的返回按钮固定跳 `#/home`，从抽签结果进详情后返回不会回到「今天去哪」。本期若不动 `detail.js`，需在交付说明中列为已知限制；QA 用浏览器后退验证 `#/whereto` 会话结果保留即可。
4. **随机可测试**：不要用 `sort(() => Math.random()-0.5)` 这类不可控写法；用洗牌袋保证“相邻不重复”，并在池为 1 时给 toast，而不是返回空。随机只读 `listSpots`，不写任何存储。
5. **空态与异常分开处理**：`listSpots()` 返回 `[]` 是空态；抛异常/返回非数组是错误态。两种文案和动作不同，不要合并成同一个“暂无数据”。
6. **不要在抽签页调用定位**：本页不显示距离、不需要 `navigator.geolocation`；避免用户刚进新 tab 就被权限弹窗打断。
7. **图片降级链**：`cover` → `images[0]` → 纸张色分类占位；`img.onerror` 必须隐藏破图并显示占位，不能留灰框。
